## §1 逐笔数据流的市场结构差异

### §1.1 数据流的三元组结构

**※【定义】** 逐笔数据流

设交易时段 $T$ 内某市场的逐笔数据流为三元组 $(\mathcal{O}, \mathcal{T}, \mathcal{S})$，其中 $\mathcal{O}=\{o_i\}_{i=1}^{N_O}$ 为逐笔委托流(Order stream)，$\mathcal{T}=\{t_j\}_{j=1}^{N_T}$ 为逐笔成交流(Trade stream)，$\mathcal{S}=\{s_k\}_{k=1}^{N_S}$ 为快照流(Snapshot stream)。每条记录携带时间戳 $\tau$，且 $\mathcal{O}$、$\mathcal{T}$、$\mathcal{S}$ 通过独立通道异步推送。

### §1.2 撤单记录的市场嵌入位置

**※【定义】** 撤单事件的市场嵌入

设 $\mathcal{C}$ 为撤单事件集合。不同市场将 $\mathcal{C}$ 嵌入不同数据流：

- 深交所：$\mathcal{C}^{SZ} \subset \mathcal{T}^{SZ}$，撤单以类型标识 $\tau=1$ 出现在成交流中；
- 上交所：$\mathcal{C}^{SH} \subset \mathcal{O}^{SH}$，撤单以 $\text{OrdType}=\text{'D'}$ 出现在委托流中；
- 中金所：$\mathcal{C}^{CFFEX} \subset \mathcal{O}^{CFFEX}$，撤单以状态字段标识出现在委托流中。

**※【命题】** 撤单的成交流可见性

在常规Level-2权限下，上交所成交流满足 $\mathcal{C}^{SH} \cap \mathcal{T}^{SH} = \varnothing$；深交所成交流满足 $\mathcal{C}^{SZ} \subset \mathcal{T}^{SZ}$。

**证明** 上交所撤单记录仅存在于逐笔委托流 $\mathcal{O}^{SH}$ 中，常规Level-2权限不提供 $\mathcal{O}^{SH}$，故 $\mathcal{T}^{SH}$ 不含撤单记录。深交所将撤单作为特殊成交类型写入 $\mathcal{T}^{SZ}$，故在成交流中可见。证毕。

### §1.3 推送频率机制

**※【定义】** 事件驱动推送

设事件序列 $\{e_n\}$ 的发生时刻为 $\{t_n\}$。事件驱动推送(Event-driven push)满足推送时刻 $p_n = t_n + \delta_n$，其中 $\delta_n \geq 0$ 为传输延迟，推送与事件一一对应。深交所逐笔数据采用此机制。

**※【定义】** 窗口聚合推送

设窗口宽度为 $\Delta$。窗口聚合推送(Window-aggregated push)在时刻 $p_m = m\Delta$ 推送窗口 $W_m = ((m-1)\Delta, m\Delta]$ 内的聚合状态。中金所Level-2快照取 $\Delta = 500\text{ms}$；上交所快照节奏与 $\Delta = 3\text{s}$ 关联较强。

**※【命题】** 窗口聚合的时序压缩

设窗口 $W_m$ 内发生 $K$ 个事件，其发生时刻满足 $t_{m,1} < t_{m,2} < \cdots < t_{m,K}$。在聚合快照层面，若 $K \geq 2$，则严格时序关系 $\{t_{m,k}\}_{k=1}^{K}$ 不可从单一快照记录中还原。

**证明** 快照仅记录窗口末端 $p_m$ 时刻的状态截面，窗口内各事件的独立时间戳在聚合时被压缩为单一刷新时刻。故 $K \geq 2$ 时，事件间的严格先后关系不可从快照中恢复。证毕。

**※【命题】** 静默窗口不推送

中金所快照机制下，若窗口 $W_m$ 内无任何委托或成交变化，则不产生对应推送记录，即推送序列 $\{p_m\}$ 在时间轴上稀疏且不均匀。

## §2 订单生命周期与委托-成交链接

### §2.1 订单生命周期的状态序列

**※【定义】** 订单生命周期

设委托编号为 $id$，其生命周期(Order lifecycle)为状态序列

$\ell(id) = (s_1, s_2, \ldots, s_n)$

其中 $s_i = (t_i, \sigma_i, q_i)$，$t_i$ 为时刻，$\sigma_i \in \{\text{新增}, \text{成交}, \text{撤销}\}$ 为状态，$q_i$ 为数量。

**※【定义】** 委托编号链接键

逐笔成交流中的每条记录 $t_j \in \mathcal{T}$ 携带买方委托编号 $id_j^B$ 与卖方委托编号 $id_j^S$，满足 $t_j$ 由 $\ell(id_j^B)$ 与 $\ell(id_j^S)$ 中的成交状态触发。委托编号 $id$ 是 $\mathcal{O}$ 与 $\mathcal{T}$ 之间的核心链接键。

**※【命题】** 委托流与成交流的因果链接

每笔成交记录 $t_j$ 可回溯至 $\mathcal{O}$ 中至少两条委托记录（买方新增与卖方新增），满足

$t_j \mapsto \{o_i \in \mathcal{O} : o_i.id \in \{id_j^B, id_j^S\}\}$

**证明** 成交流仅记录撮合结果，不包含完整订单信息；委托流记录意图与状态变化。通过委托编号反向索引，可将成交结果映射至触发它的委托记录。证毕。

**※【命题】** 撤单的委托流归属

撤单事件 $c \in \mathcal{C}$ 在委托流中表现为状态 $\sigma = \text{撤销}$ 的记录，不在成交流中产生独立成交记录。

**证明** 撤单是委托生命周期的状态节点，不涉及撮合，故不进入成交流。深交所将撤单嵌入成交流（$\tau=1$）属于数据封装约定，不改变其非成交本质。证毕。

### §2.2 部分成交与状态漂移

**※【命题】** UpdateTime的状态漂移

对同一订单 $id$，其状态序列 $\ell(id)$ 中相邻状态满足 $\text{UpdateTime}(s_i) \leq \text{UpdateTime}(s_{i+1})$，且当 $\sigma_i \neq \sigma_{i+1}$ 或 $q_i \neq q_{i+1}$ 时，$\text{UpdateTime}(s_{i+1}) > \text{UpdateTime}(s_i)$。

**证明** $\text{UpdateTime}$ 定义为记录最近一次被更新的时刻，每次状态变化（部分成交、改单、撤单）均刷新该字段，故状态变化时严格递增。证毕。

## §3 盘口、成交、委托的对应关系

### §3.1 盘口快照作为状态截面

**※【定义】** 盘口快照

时刻 $t$ 的盘口快照 $S(t)$ 为订单簿状态的截面，包含 $k$ 档买卖价格与数量：

$S(t) = \{(P_i^B, Q_i^B, P_i^A, Q_i^A)\}_{i=1}^{k}$

其中 $P_i^B, Q_i^B$ 为第 $i$ 档买价与买量，$P_i^A, Q_i^A$ 为第 $i$ 档卖价与卖量。

### §3.2 非一一对应性

**※【命题】** 盘口-成交-委托的非一一映射

设 $o_i \in \mathcal{O}$ 为一笔委托新增记录，$t_j \in \mathcal{T}$ 为一笔成交记录，$S(t)$ 为盘口快照。三者不构成一一映射：

- 存在 $o_i$ 不产生任何 $t_j$（挂单未成交或被撤）；
- 存在 $t_j$ 消耗多个价格档位，不显式标注对应档位；
- 存在 $S(t)$ 的变化由无成交的委托引起。

**证明** 委托流与成交流是原因端的事件记录，盘口快照是结果端的状态截面。委托可停留或撤销而不成交，成交可跨档位撮合，挂撤单可改变盘口而无成交。三者通过时间戳与逻辑序号对齐，而非天然一一对应。证毕。

**※【命题】** 异步通道的时序偏差

在独立通道推送机制下，同一逻辑事件在 $\mathcal{O}$、$\mathcal{T}$、$\mathcal{S}$ 中的到达时刻不一定相同，存在可观测的时延差 $\delta_{XY} = |\tau_X - \tau_Y|$，其中 $X, Y \in \{\mathcal{O}, \mathcal{T}, \mathcal{S}\}$。

**证明** 三条流通过独立通道并行推送，网络传输与交易所封装路径不同，导致到达本地的时间先后不一致。实测通道间平均到达时延差可达毫秒级。证毕。

## §4 时间戳语义

**※【定义】** HappenedTime与UpdateTime

- $\text{HappenedTime}(e)$：事件 $e$ 真实发生的时刻，一次性赋予且在整个生命周期内不变；
- $\text{UpdateTime}(e)$：记录 $e$ 最近一次被更新的时刻，随状态变化而刷新。

**※【命题】** 时间戳的偏序关系

对同一订单 $id$，其状态序列 $\ell(id)$ 满足

$\text{HappenedTime}(s_1) \leq \text{HappenedTime}(s_2) \leq \cdots \leq \text{HappenedTime}(s_n)$

且 $\text{UpdateTime}(s_i) = \text{HappenedTime}(s_i)$ 当且仅当 $s_i$ 是该记录的最新状态。

**证明** $\text{HappenedTime}$ 为事件诞生时刻，在生命周期内单调不减；$\text{UpdateTime}$ 随每次状态变化刷新，仅在最新状态下与 $\text{HappenedTime}$ 重合。证毕。

**※【命题】** 延迟归因的基准选择

设本地接收时刻为 $\tau_{\text{recv}}$。用 $\text{UpdateTime}$ 估计端到端延迟会系统性低估真实延迟，即

$\tau_{\text{recv}} - \text{UpdateTime}(e) \leq \tau_{\text{recv}} - \text{HappenedTime}(e)$

**证明** 在聚合快照中，$\text{UpdateTime}$ 为窗口末端刷新时刻，晚于窗口内原始事件的 $\text{HappenedTime}$。故以 $\text{UpdateTime}$ 为基准的延迟估计偏小。证毕。

## §5 因子构造中的数据粒度

### §5.1 tick bar与分钟bar的定义

**※【定义】** 分钟bar

设价格序列为 $\{P_n\}$，成交量序列为 $\{V_n\}$。第 $m$ 分钟bar为

$B_m^{\min} = (O_m, H_m, L_m, C_m, V_m)$

其中 $O_m = P_{n_1}$，$C_m = P_{n_2}$，$n_1, n_2$ 为第 $m$ 分钟首尾成交索引，$H_m = \max_{n_1 \leq n \leq n_2} P_n$，$L_m = \min_{n_1 \leq n \leq n_2} P_n$，$V_m = \sum_{n=n_1}^{n_2} V_n$。

**※【定义】** tick bar

第 $k$ 个tick bar为

$B_k^{\text{tick}} = (O_k, H_k, L_k, C_k, V_k)$

其中 $O_k = P_{n_1}$，$C_k = P_{n_2}$，$n_1, n_2$ 为第 $k$ 个bar首尾成交索引。bar的切分方式可为固定笔数、固定时间（如 $500\text{ms}$）或固定成交量，不同切分方式下 $O_k, C_k$ 的语义不同。

**※【命题】** 因子信息含量的粒度差异

tick OHLCV保留订单流微观结构，分钟OHLCV为时间聚合摘要。同一逻辑构造的因子在两种粒度下分布不同，不可简单聚合迁移。

**证明** 分钟bar的 $V_m$ 为 $60\text{s}$ 总量，无法区分大单连续吃与小单密集成交；tick bar的 $V_k$ 配合逐笔流可识别单笔大单与瞬时撤单。聚合操作改变分布特性与自相关结构，故同一逻辑在两种粒度下不等价。证毕。

**※【命题】** 中金所 $500\text{ms}$ 快照bar的特殊性

中金所 $500\text{ms}$ 快照OHLCV的bar为固定窗口聚合，其半衰期与信噪比介于tick因子与分钟因子之间。当窗口内仅一笔成交时，$O=H=L=C$，此时 $(H-L)/C=0$。

**证明** $500\text{ms}$ 窗口内若仅一笔成交，则首尾价与极值均为同一价格，振幅为零。分钟bar在非停牌情况下几乎不出现此退化情形。故中金所快照bar需特殊处理零振幅窗口。证毕。
